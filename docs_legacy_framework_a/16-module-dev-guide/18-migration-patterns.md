# Migration Patterns

**MDG-018 | Status: Accepted | Stability: Stable**

Standard migration templates for common schema changes. Copy and adapt for new modules.

---

## 1. New System Entity Table

```sql
-- 20241215143022_create_finance_invoice.up.sql
CREATE TABLE finance_invoice (
    -- Primary key (always UUID v7, provided by application)
    id              uuid PRIMARY KEY,

    -- Tenant isolation (always present, always first after id)
    tenant_id       uuid NOT NULL REFERENCES tenants(id),

    -- NamingSeries field (generated by framework, NOT NULL after first save)
    number          varchar(50),

    -- FK to linked entity
    customer        uuid NOT NULL REFERENCES crm_customer(id),

    -- Select field (SQL CHECK constraint for valid values)
    status          varchar(50) NOT NULL DEFAULT 'Draft'
                    CHECK (status IN ('Draft', 'Submitted', 'Approved', 'Rejected', 'Paid', 'Cancelled')),

    -- Currency field (numeric(20,4) — NEVER float)
    total_kes       numeric(20,4) NOT NULL DEFAULT 0,
    vat_kes         numeric(20,4) NOT NULL DEFAULT 0,

    -- Date fields
    invoice_date    date NOT NULL DEFAULT CURRENT_DATE,
    due_date        date,

    -- Long text
    notes           text,

    -- Custom fields (JSONB — every system entity has this)
    custom_fields   jsonb NOT NULL DEFAULT '{}',

    -- Standard timestamps (always present)
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),

    -- Soft delete (include if entity supports deletion)
    deleted_at      timestamptz
);

-- Row-Level Security (MANDATORY for every tenant-scoped table)
ALTER TABLE finance_invoice ENABLE ROW LEVEL SECURITY;
ALTER TABLE finance_invoice FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON finance_invoice
    USING (tenant_id = current_tenant_id());

-- Indexes
CREATE INDEX ON finance_invoice(tenant_id);
CREATE INDEX ON finance_invoice(tenant_id, status);  -- filtered by status frequently
CREATE INDEX ON finance_invoice(customer);             -- FK lookup
CREATE INDEX ON finance_invoice USING gin(custom_fields);  -- custom field queries
-- If name/number is searchable:
-- CREATE INDEX ON finance_invoice USING gin(number gin_trgm_ops);
```

```sql
-- 20241215143022_create_finance_invoice.down.sql
DROP TABLE IF EXISTS finance_invoice;
```

## 2. Add Column (Zero-Downtime)

```sql
-- Step 1: Add nullable column first (no default required, no table rewrite)
-- 20241220_add_approved_by_to_finance_invoice.up.sql
ALTER TABLE finance_invoice
    ADD COLUMN approved_by uuid REFERENCES iam_user(id),
    ADD COLUMN approved_at timestamptz;
```

```sql
-- down
ALTER TABLE finance_invoice
    DROP COLUMN IF EXISTS approved_by,
    DROP COLUMN IF EXISTS approved_at;
```

For columns that will eventually be NOT NULL:
1. Migration 1: Add nullable
2. Backfill via separate migration or background job
3. Migration 2: Add NOT NULL constraint (after backfill)

**Never add a NOT NULL column without a DEFAULT in a single migration** — it locks the table.

---

## 3. Add Index (Zero-Downtime)

```sql
-- 20241221_add_status_idx_finance_invoice.up.sql
-- CONCURRENTLY = no table lock — required for production
CREATE INDEX CONCURRENTLY idx_finance_invoice_status_tenant
    ON finance_invoice(tenant_id, status)
    WHERE deleted_at IS NULL;  -- Partial index — only active records
```

```sql
-- down
DROP INDEX CONCURRENTLY IF EXISTS idx_finance_invoice_status_tenant;
```

## 5. Child Table (One-to-Many)

```sql
-- 20241223_create_finance_invoice_line.up.sql
CREATE TABLE finance_invoice_line (
    id          uuid PRIMARY KEY,
    tenant_id   uuid NOT NULL REFERENCES tenants(id),

    -- FK to parent (always NOT NULL, always Immutable)
    invoice     uuid NOT NULL REFERENCES finance_invoice(id) ON DELETE CASCADE,

    -- Line-specific fields
    description varchar(500) NOT NULL,
    quantity    numeric(20,4) NOT NULL CHECK (quantity > 0),
    unit_price  numeric(20,4) NOT NULL CHECK (unit_price >= 0),
    total       numeric(20,4) NOT NULL,

    custom_fields jsonb NOT NULL DEFAULT '{}',
    created_at    timestamptz NOT NULL DEFAULT now(),
    updated_at    timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE finance_invoice_line ENABLE ROW LEVEL SECURITY;
ALTER TABLE finance_invoice_line FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON finance_invoice_line
    USING (tenant_id = current_tenant_id());

CREATE INDEX ON finance_invoice_line(tenant_id);
CREATE INDEX ON finance_invoice_line(invoice);  -- Parent FK lookup
CREATE INDEX ON finance_invoice_line USING gin(custom_fields);
```

## 6. Rename Column (Multi-Step)

Never rename a column in a single migration. Use the dual-write pattern:

**Step 1** (deploy with dual-write):
```sql
-- Add new column
ALTER TABLE finance_invoice ADD COLUMN due_date date;
-- Backfill from old column
UPDATE finance_invoice SET due_date = payment_due WHERE payment_due IS NOT NULL;
```

**Step 2** (after full deployment and verification — next sprint):
```sql
-- Old column no longer written — safe to drop
ALTER TABLE finance_invoice DROP COLUMN payment_due;
```

## 8. Global Table (No RLS)

For reference data shared across all tenants:

```sql
-- 20241225_create_paye_bands.up.sql
CREATE TABLE paye_bands (
    id          bigserial PRIMARY KEY,
    upper_bound numeric(20,4) NOT NULL,  -- Monthly taxable income upper bound
    rate        numeric(5,2) NOT NULL,   -- Tax rate percentage
    effective_from date NOT NULL,
    effective_to   date,
    UNIQUE (upper_bound, effective_from)
);

-- No RLS on global tables
-- App role has SELECT only — INSERT/UPDATE/DELETE via migration role only

GRANT SELECT ON paye_bands TO app_role;

-- Seed data
INSERT INTO paye_bands (upper_bound, rate, effective_from) VALUES
    (24000,  10.0, '2024-01-01'),
    (8333,   25.0, '2024-01-01'),
    (467667, 30.0, '2024-01-01'),
    (300000, 32.5, '2024-01-01'),
    (800000, 35.0, '2024-01-01');
```
